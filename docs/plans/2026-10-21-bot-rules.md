# Bot rules — the user's decisions, a row each, and a folder for the rest

Decided 2026-10-21, after the notes of `2026-10-18-bot-memory.md` (phase 3)
were in daily use, and an A/B run (branch `prototype/bot-memory-ab`, thrown
away) of the variant below against them.

## Why

- Notes were one text split by `§`, and the bot could not address an entry.
  `memory patch {old_text, content}` replaced the whole entry that held
  `old_text`: a bot lost a long entry trying to change one phrase. `remove`
  matched by substring, and the bot sheet needed a text-equality `merge()` to
  lay the user's edit over what the bot wrote meanwhile.
- The tool was called `memory` and its text invited ids, prices and pending
  work, so bots dumped everything there. The 4,000 characters filled with
  state that went stale.
- What should outlive a turn as text in front of the bot is small: the
  user's decisions about how it works ("Never push to master", "Run the tests
  before pushing"). Everything else is in the conversation, which
  `read_session` searches, or belongs in files.

## Decisions

- **One row per rule** (`bot_rules`, migration 41), keyed by the bot's id
  like `bots` (a bot and its session share the id; `bot_notes` was keyed by
  the session, the same value). A rule's id is a number within its bot
  (`number`, unique per bot), shown and taken as `r3` everywhere: the
  prompt, the tool, the CLI, the RPC and the sheet. A number is never given
  twice: `bots.rules_made` counts the rules a bot has had, so removing the
  newest does not free its number. One more column: `source`
  (`bot` | `sheet` | `notes`), because a rule with no cited message is either
  the user's own from the sheet, shown `(user, <day>)`, or migrated from the
  notes, shown with no attribution; nothing else tells the two apart.
- **Migration**: every `bot_notes` body is split on its `§` lines into rows,
  numbered from 1 within each bot (`source = 'notes'`, no message, both
  times the notes' `updated_at`), then `bot_notes` is dropped. Per-bot
  numbers came after the first A/B run, and since migration 41 had not
  shipped in a release it was changed in place rather than followed by
  another: a data dir made by the earlier build of this branch has to be
  made again. Migrations here do drop what they replace (v37
  dropped `archived`). Bodies are stored tidied: one line, whitespace
  collapsed, since the prompt shows a rule per line.
- **Cap 1,500 characters** summed over bodies. A write that leaves the rules
  over it and longer than they were is refused whole; one that shrinks them
  goes through, so rules migrated from a full notebook (up to 4,000) can be
  brought back under. The sheet's save is one transaction under the same
  check.
- **`rules` replaces `memory`**, bots only: `add {content, from}`,
  `edit {id, content, from?}`, `remove {id}`. An edit given `from` (the
  message where the user changed their mind) cites that message from then
  on, under the same check as an add; without it the citation stays. `from` must be the block number of a
  message the user typed: not a letter from a bot or a session (`from_bot`),
  not the bot's own text, not a crew line, not a routine's prompt (a hidden
  user block). The rule stores that message's id. An exact repeat answers
  `already r3`. Answers are one line (`added r3`, `edited r2`, `removed r1`
  or the refusal), never the list: tool results end up in the trail, and the
  rules are at the top of the turn already. No `show`.
- **Every change the bot makes is a crew line** in its chat (`Rule added:
  "…"`, `Rule edited: "…"`, `Rule removed: "…"`), as "Description updated by
  itself" is. The sheet's edits are the user's own and say nothing.
- **The description** is who the bot is, its job and where it works. The bot
  may write at most 2,000 characters into it; the user's edit in the sheet is
  not capped.
- **The bot's folder** is `<work dir>/workspaces/<workspace>/bots/<bot>/`,
  stored on the bot (`bots.folder`, migration 42) the first time a turn needs
  it, from the names then. Stored rather than derived from the current names:
  a rename would otherwise move the bot away from what it kept, and two bots
  whose names make the same path (the same name in two workspaces of the same
  name) would share it; the second gets `-2`. It is made on the bot's first
  turn, deleted with the bot or its workspace (only ever under
  `<work dir>/workspaces/`). The prompt says one line about it and nothing of
  what goes there. No `shared/` folder for now.
- **The trail**: a message the user typed leads with its block number
  (`[#20 · 2026-10-21 14:08 · user]`), and only those, so every number shown
  is one `from` accepts. The turn's header says which block the new message
  took (`## This turn (block N)`, or `blocks N-M` for a batch of letters); it
  is computed after the message is appended, from the transcript's length,
  and the trail now carries it, so `assemble` no longer adds a header. An
  assistant reply before the user's latest message is its first paragraph and
  ` (+N chars, block K)`, still clipped at 600; the latest reply is whole. A
  `rules` call is its own line (`rules: added r3`, `rules: refused`), never
  folded into a run of tools. `TAIL_BUDGET` 20,000 → 12,000.

## Writing to the folder, per provider

| Provider | How it may write there | `CREW_SCRATCH_SELF` |
|---|---|---|
| claude | `--add-dir <folder>` | CLI env |
| codex | `sandbox_workspace_write.writable_roots` on `thread/start` (a bot's process is never kept, so no `turn/start` override is needed); full runs unsandboxed | CLI env |
| cursor | `--add-dir <folder>` before `acp` (in `cursor-agent --help`; not yet seen live under ACP) | CLI env |
| opencode | an `external_directory` allow rule for `<folder>/*` after the ask rules (full allows everything) | the session's shell environment |
| grok | no equivalent flag: a write outside the folder it runs in goes through its permission mode (asks unless full) | CLI env |

## What changed

- `crates/crew-core/src/rules.rs` (was `notes.rs`): storage, migration,
  `apply` (all-or-none, cap), `user_message`, prompt lines, usage.
- `crates/crew-core/src/bot_folder.rs`: assign, make, remove.
- `tools.rs`: `rules`, the description cap, new descriptions for
  `update_description` and `create_bot`'s `description`. CLI: `crew bots rules
  add --from 12 …`, `edit --id r3 …`, `remove --id r3`.
- `prompts.rs`: `### Your rules [22% - 335/1,500]` with
  `[r1] Never push to master. (user, 2026-10-21)` lines, the folder line, and
  "Do the work first, then say what happened in a few lines, leading with the
  result."
- `working_set.rs`, `turns.rs`, `providers/mod.rs`: numbering, header,
  first paragraphs, the `rules` line, the budget.
- Providers: `ClaudeSpawn`/`CursorSpawn::add_dirs`,
  `CodexThread::writable_roots`, opencode's rules and shell env.
- Protocol: `bot_rules_get {id}` → `BotRules`, `bot_rules_save {id, add,
  edit, remove}` → `BotRules` replace `bot_notes_get`/`bot_notes_set`.
- Bot sheet: `BotRules.tsx`, `useBotRules`, `lib/botRules.ts`. A row per
  rule, edited and removed by id; under a rule the bot added, the start of the
  user's message it cites and its day. The description's hint: "Who it is, its
  job and where it works. Read every turn."
